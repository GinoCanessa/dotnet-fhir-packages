## Ownership and Failure Rules

- One `FileSystemContext` retains an immutable effective policy. Each value uses
  an explicitly assigned SDK property / CLI flag, then its environment variable,
  then its default. Defaults are **5 retries after the first execution**, **10 ms
  minimum delay**, and fresh inclusive uniform **[0, 10] ms** additive jitter.
  Exhaustion is six executions and five waits totaling 50–100 ms, excluding OS
  execution time. Zero retries means one execution.
- Effective values must be nonnegative `Int32` integers; empty, negative,
  malformed, and overflowing environment values are invalid. Minimum delay plus
  maximum jitter must be at most `Int32.MaxValue`, with no smaller cap. Delay
  bounds and total attempts use wide arithmetic. SDK failures are
  `PackageInstallException` with code `InvalidPolicy` and stage
  `PolicyValidation` before affected I/O;
  CLI policy/option errors exit `2` before discovery, config, or tarball work.
- `FileSystemRetryExecutor.Execute` / `ExecuteAsync` are the **sole fault
  scheduler**. Raw managed/native seams and legacy forwarders have **zero private
  fault loops**. A primitive establishes filesystem origin and replay safety;
  this is not a transient-error allowlist or a catch around arbitrary code.
  No wait precedes initial work; success and exhaustion have no following wait.
  Each eligible retry has exactly one fresh jitter sample and wait.
- A replay unit owns its remaining budget and completed phases. Open, a later
  block read/write, and cleanup are distinct units, not an aggregate install
  budget. Compound path resolution/mutation/barriers and read recovery share
  their unit's remaining budget. Protected streams are not rewrapped, and a
  terminal local failure cannot receive a fresh budget through fallback.
- Expected absence, file-kind rejection, and ordinary contention are semantic
  outcomes. A required manifest that disappears **after inventory selection**
  remains a required-read fault with existing typed wrapping, not optional
  absence. JSON/gzip/tar errors, checksums, identity/limit validation, cancellation,
  and observer callbacks are not fault-retry signals.
- Async domain companions await `ExecuteAsync` waits, including synchronous
  native calls inside async protocols. Constructors, synchronous public helpers,
  and compatibility entry points remain synchronous. Borrowed-file preparation
  and ownership release are deliberately one-shot. There is no `Task.Run` bridge
  or retry of a whole parser, transaction, extraction, or HTTP operation.
- Final failures retain exception identity/type/stack/native inner error and
  internal operation/path/phase/attempt/native-code/flag context. Existing
  Corrupt/Repair/Strict, optional-index regeneration, result conversion, and
  best-effort cleanup remain domain decisions after exhaustion. Reason-only
  results and CLI messages retain final context without new public result fields.
- Normal cache-lock coordination remains unbounded with its separate 10–250 ms
  backoff. Fault retries do not bound an OS call, lock wait, complete operation,
  or deliberately uncancellable commit/recovery section.

## Standalone Helpers and Archive Work

Public filesystem helpers resolve once per invocation when they need a new
context; internal graph overloads receive the existing context. Memory-only
parsing/hashing does not read retry environment or start I/O; reusing an
already-protected input does not resolve settings or add a budget. APIs with
filesystem destinations still resolve policy for their output. There are no
public retry-options overloads on the manifest/checksum/INI/temp/archive/key helpers;
their internal context-taking overloads are not a new public API.

## Deliberate Non-Replay Boundaries

These are concrete ownership/safety boundaries, not missing supported-platform
implementations or a blanket “unsupported stream/platform” exemption.

| Path / operation | Why it does not own filesystem retries |
|---|---|
| Pure models/interfaces, `PackageArchiveContentLocator` inventory decisions, `PortableArchivePath`, `PackageFixups`, version/directive matching, `MemoryResourceCache`, in-memory indexes, manifest strings and checksum byte arrays | No OS-backed work. Pure parsing and absolute path/containment calculations do not resolve retry environment. Returned raw paths are not SDK-owned future reads. |
| Arbitrary/derived `FileStream`, opaque wrappers, memory/network/nonseekable streams supplied by callers | The SDK cannot prove stable handle, position recovery, or absence of hidden write effects and does not unwrap them. Existing one-shot consumption/ownership remains. `BorrowedFileReadStreamTests.OpaqueOrNonSeekableStream_IsReadOnce` and `RegistryClientBaseTests.PutStream_OpaqueSourceFailureIsConsumedOnceWithoutFilesystemRetries` cover the distinction. |
| Borrowed-file flush/handle/checkpoint preparation; ambiguous mutation; close/dispose | Possible partial caller writes or already-completed mutation/released descriptor cannot be blindly replayed. These failures are terminal unsafe one-shot, with final context and primary-error precedence. This preserves read/write file compatibility and release safety on Windows/Linux/macOS. |
| Direct INI mutation with Unix reader sharing | Existing shared flock is not exclusive-writer proof. Preserve `FileShare.Read`, but fail a failed write/truncate/set-length once; do not pretend path existence or a seekable handle proves safety. Windows deny-write sharing and exclusive durable writers retain proven-safe replay. |
| `StreamReader`, JSON serializers, hash/encoding/base64 work, gzip/tar (`TarMetadataPreflightStream`) | File input is protected **below** these consumers; parsers/observers and accepted bytes are not replayed. Malformed content/limits/checksum/identity failures remain semantic, with existing typed outcomes. |
| `DeadlineAwareHttpStream`, `RegistryClientBase` response-owning/non-disposing wrappers, HTTP response bodies and HTTP destination writes | Network/transport ownership, not filesystem work. Adapt recognized files before SDK wrappers hide them, prepare file metadata before HTTP callbacks, and never retry an emitted HTTP body or destination write. Existing network redirects/healthy reserialization are not filesystem fault retries. |
| Third-party caches/indexers/registries/resolvers/managers/resource implementations | Their private I/O is opaque; no new capability interface, reflection, mutation, or policy enforcement is imposed. Built-in held graphs alone are traversed for explicit-manager checks. |
| `tools/FhirPkg.Release/`, `test/FhirPkg.Qualification/`, `test/FhirPkg.ProcessTestHost/`, fixture/setup I/O | Not shipping SDK/CLI policy consumers. Feature tests inject faults below the boundary; the unchanged process host exercises compatibility/cross-process coordination. No external retained fixture archive was downloaded for this gate. |
